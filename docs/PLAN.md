# 项目扫描与文档沉淀计划

本文档是本轮“全项目扫描 + MEMORY/博客稿沉淀”的执行清单。当前状态为已执行版，可作为后续扩展文档时的入口。

## 1. 目标与原则

本轮产出两份正式文档：

- `docs/MEMORY.md`
  - 面向维护者的当前实现事实手册
- `docs/PROJECT_INTRODUCTION.md`
  - 面向外部发布的项目介绍稿，要求脱敏、正式术语、只讲当前有效实现

执行原则：

- 以当前真实运行链路为准，不以历史方案文档为准
- 事实优先级：
  1. 代码与配置
  2. 模板与静态资源
  3. 现有 MEMORY
  4. README / 分析稿 / 原型目录
- 对历史原型只做边界标注，不混入当前实现描述

## 3. 模块扫描顺序与执行结果

### 模块 1：启动入口与运行模式

- 状态：已完成
- 结论：
  - 主入口是 `ToolServiceApplication`
  - 当前项目是 Spring Boot 单体服务
  - 当前可用产品是 HTTP + MCP 接口，以及 `/md-view` 页面工作台

### 模块 2：配置体系与优先级

- 状态：已完成
- 结论：
  - `application.yml` 负责导入模块化配置
  - 运行目录 `config/` 中的配置优先于 classpath 默认配置
  - Markdown 工作目录支持用户级配置和桌面回退
  - 数据库与 MCP 暴露受功能开关控制

### 模块 3：数据源与数据库服务

- 状态：已完成
- 结论：
  - 当前固定数据源是 `master` 与 `sso`
  - 其他数据库名按需动态创建连接池
  - 查询、更新、DDL、自动分流、表清单、表结构和历史记录均已实现

### 模块 4：MCP 协议层与工具暴露

- 状态：已完成
- 结论：
  - 同时提供 REST 风格与 JSON-RPC 风格入口
  - 工具分为数据库工具和 Markdown 工具
  - 当前 MCP 控制器整体受数据库功能开关控制

### 模块 5：Markdown 预览后端接口

- 状态：已完成
- 结论：
  - 页面入口、工作目录接口、壳层接口、文档接口、原文/下载/保存接口完整存在
  - `path` 与 `scope` 有统一规范化与越界保护
  - 工作目录切换与文档保存会触发缓存失效

### 模块 6：Markdown 预览前端交互与状态

- 状态：已完成
- 结论：
  - 页面包含左树、标签栏、面包屑、预览/原文、TOC、请求调试面板
  - 大量交互状态依赖 localStorage
  - 左树、TOC、标签、面板、面包屑已形成完整联动

### 模块 7：缓存与性能链路

- 状态：已完成
- 结论：
  - 后端已实现侧栏 TTL 缓存与文档精准缓存
  - 前端已拆分壳层加载与文档加载
  - 请求层通过 AbortController 和序列号做并发保护

### 模块 8：历史原型与当前实现边界

- 状态：已完成
- 结论：
  - React/Vite 与 Node server 是并存原型，不是当前主发布链路
  - README 当前口径与真实实现不一致
  - 架构分析文档属于建议稿，不应当作事实源

### 模块 9：运维与构建约束

- 状态：已完成
- 结论：
  - Maven 是当前主构建方式
  - `clean` 阶段可能受运行中模板文件占用影响
  - 目录选择器依赖图形环境

## 4. 每个模块必须回答的问题

后续若扩展文档，仍沿用以下问题模板。

### 启动入口与运行模式

- 当前应用主入口是什么？
- 启动后实际暴露哪些能力？
- 当前“真正可用产品”是哪条链路？

- 配置文件加载顺序是什么？
- 哪些配置来自外部覆盖？
- 哪些是功能开关，哪些是运行时状态？
